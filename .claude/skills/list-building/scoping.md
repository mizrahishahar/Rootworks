Teaches: the market read and the first call of a build. How many lists a brief warrants, how big each should be, where the TAM lives, and what comes after a list runs dry.

# Scoping

The first call, and the one that shapes everything downstream: how many lists does this brief warrant, and how does each open? A list, a vertical, a query: the same thing, named for where you're standing when you say it. One number and a spec per list. Each becomes one major pull, one CSV, one table, and usually the spine of its own campaigns.

## What makes one list

One sentence, specifically true. Can you write one description that is specifically, not generically, true for everyone this list should return? If the sentence has to go generic to cover everyone, there are two lists, not one. That's the whole test at this stage. Whether a thin or similar-sounding list should fold into another instead is a size-and-a-reason question, and that question belongs to segmentation, once real rows exist to read it against.

Narrow enough has the same test from the copy side: one specific copy line is true for everyone on the list. That is the measure, not a TAM number.

## Read the brief first

A build arrives as a handoff: the offer, who to reach, which source opens the build, any domains already in hand, prior results. The brief names the opening, company-first (a discovery source) or contact-first (a contact database). The source's interface defines how its query is shaped and what it outputs; this call carries the judgment that stays constant across every source: how many lists.

## Sizing: the ratios that back-calc a list

Thumb-rules, directional, and niches swing them hard (trades run far hotter than SaaS):

- ~1 meeting per 5,000 sends, ~1 positive per 750, ~1% reply, bounce under ~3%. Judge nothing under ~5,000 sends; trust an angle at 10 to 15 positives.
- Build ~1,500 to 2,500 leads per test cohort, ~1,000 to 2,000 per native segment, and hold ~10,000 to 15,000 verified to run a month without re-sourcing.

## Where the TAM lives

- **Match the source to the niche.** LinkedIn-anchored tools cover a fraction of blue-collar, SMB, private, and international markets (HVAC surfaces ~2-4% on Apollo); web-indexed discovery reaches that long tail. Never trust one source to hold a whole market.
- **The floor:** under ~1,000 reachable prospects, cold email breaks; pivot the client toward ABM or calling.
- For firms under ~10 employees, add public and role emails alongside personal ones.

## Depth vs breadth

Thin TAM wins on depth: more enrichment, sharper personalisation, more touches per lead. Wide TAM wins on volume and segmentation, and enrichment stays lighter.

## Refill: what comes after this list

Decay is physics: reply rates fall across a sequence, and re-hitting leads decays them faster. The fix is fresh leads, not copy tweaks, and the refill gets built before the current pool runs dry. The expansion ladder, chosen by what has already been run: segment harder, then widen a filter or the geo, then mine the client book for profitable sub-verticals, then a new data source, then recycle as a last resort.

## Name the segments each list already implies

The segments a split into multiple lists already implies are set here, not later: a two-list build is at least two campaigns. Naming them at scoping is what secures the variables, because the pulls must carry what the intended segments will select on (discovery extraction variables, contact-level fields). Designing segments only after ingest is what forces expensive base fixes. The full segment set still waits for the base and the real distribution.

## The spec you hand over

Per list: the audience in one specific sentence, the description or filter set in the source's own language, the suggested filters or seeds worth setting, and the variables the intended segments need on the rows. Make it as easy as possible to run well.

## How to show it

One real markdown table, one row per list, never prose paragraphs and never a table inside a code fence:

| List | The audience, one sentence | Source and opening | Est. size | Variables to ride with the pull |
|---|---|---|---|---|

Under the table: the implied segments per list as a short bullet list, and any judgment call worth flagging as one labeled line each.

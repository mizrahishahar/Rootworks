# Scoping the lists

The first call, and the one that shapes everything downstream: how many lists does this brief warrant, and how does each open? A list, a vertical, a query - the same thing, named for where you're standing when you say it. One number and a spec per list. Each becomes one major pull, one CSV, one table, and usually the spine of its own campaigns.

## What makes one list

One sentence, specifically true. Can you write one description that is specifically, not generically, true for everyone this list should return? If the sentence has to go generic to cover everyone, there are two lists, not one. That's the whole test at this stage - no volume check, no copy check here. Whether a thin or similar-sounding list should fold into another instead is a size-and-a-reason question, and that question belongs to segmentation, once real rows exist to read it against.

## Read the brief first

A build arrives as a handoff: the offer, who to reach, which source opens the build, any domains already in hand, prior results. The brief names the opening, company-first (a discovery source) or contact-first (a contact database). The source's interface defines how its query is shaped and what it outputs; this call carries the judgment that stays constant across every source: how many lists.

## Name the segments each list already implies

The segments a split into multiple lists already implies are set here, not later: a two-list build is at least two campaigns. Naming them at scoping is what secures the variables, because the pulls must carry what the intended segments will select on, so name those variables in the query spec (discovery extraction variables, contact-level fields). Designing segments only after ingest is what forces expensive base fixes. The full segment set still waits for the base and the real distribution.

## The spec you hand over

Per list: the audience in one specific sentence, the description or filter set in the source's own language, the suggested filters or seeds worth setting, and the variables the intended segments need on the rows. Make it as easy as possible to run well.
